# Scenary 前端审计与改进清单

> 审计日期：2026-09-02。范围：`frontend/src` 六个视图、公共组件、请求层及实际 Vite 页面。
> 本文只记录问题和验收标准，不改变前端实现。优先级含义：P0 阻断核心正确性或存在安全风险；P1 严重影响主流程/可靠性；P2 体验、可维护性和后续能力。

## 复现基线

- `cd frontend && npm run build`：通过（Vite 8.2.2，99 modules）。当前没有 lint、单元测试或 E2E 脚本。
- `npm run dev -- --host 0.0.0.0`，访问 `http://localhost:5173/`，后端未启动时可复现：页面显示“还没有风景，来发第一篇吧”，同时 toast 显示“请求失败(502)”。错误态与空态混淆。
- 同一开发服务下将 viewport 设为 `320x700`，访问 `/login`：顶部“发布”和“登录/注册”文字折成多行，按钮高度固定为 36px，观感和点击区域均异常；`390x844` 尚未折行。
- 视觉基线：默认跟随系统进入深色主题；页面只有顶部导航和中心表单/瀑布流，缺少加载、错误、刷新、筛选等可见状态。

## P0：先修复再扩展功能

### F-01 路由参数变化不会重新加载内容

- **位置**：`frontend/src/views/ProfileView.vue:12-38,106-110`、`frontend/src/views/NoteDetailView.vue:8-24`。
- **依据/复现**：`userId` 和 `onMounted` 只初始化一次，`route.params.id` 没有 `watch` 或 `onBeforeRouteUpdate`。Vue Router 对同一组件的 `/user/1 -> /user/2`、`/note/1 -> /note/2` 会复用实例；从作者链接连续打开不同用户/笔记时，旧资料/旧详情会继续显示。
- **改进**：把请求参数改成响应式 route param；在参数变化时取消旧请求、重置 `profile/detail/cards/cursor`，重新加载；保留当前路由的滚动策略。
- **验收**：在两个已存在用户和两个笔记之间连续点击，不刷新页面也能显示对应标题、作者、图片；快速连续切换时最终页面与 URL 最后一项一致，旧请求不会覆盖新数据；新增自动化用例覆盖两条路由。

### F-02 前端登出不调用后端 `/auth/logout`

- **位置**：`frontend/src/components/TopNav.vue:31-36`、`frontend/src/views/ProfileView.vue:155`、`frontend/src/stores/user.js:49-57`；后端端点为 `POST /api/v1/auth/logout`。
- **依据/复现**：两个登出入口直接 `forceLogout()`，只删除 localStorage。服务端 refresh 白名单没有吊销，已泄露的 refresh token 仍可在 TTL 内换取新 access token。
- **改进**：增加 `authApi.logout()`；登出先尽力请求服务端（失败也必须清本地状态），请求期间禁用按钮，成功/失败均跳转首页；401/网络错误不得阻止清态。增加页面关闭或多标签同步策略时要避免重复调用。
- **验收**：登出后原 refresh token 调 refresh 返回 `40101`；断网时仍能本地退出；TopNav 和 Profile 两个入口行为一致；不在日志/错误 toast 中输出令牌。

## P1：主流程可靠性与可用性

### F-03 Feed 错误被当成空数据

- **位置**：`frontend/src/views/HomeView.vue:17-32,65-74`。
- **依据/复现**：`catch` 仅发 toast，随后 `firstLoading=false`；`cards` 仍为空，于是渲染“还没有风景”。用户无法区分系统故障和真实空社区，也没有重试入口。
- **改进**：增加 `error` 状态和“加载失败，重试”按钮；错误态不能显示空态；保留已有卡片时显示内联错误并允许重试，不清空已有内容。
- **验收**：模拟 500/502、超时、断网时有稳定错误面板；点击重试可恢复；空列表仅在请求成功且 `list=[]` 时出现；错误 toast 不重复堆叠。

### F-04 详情页和个人页缺少 loading/error/retry 状态

- **位置**：`NoteDetailView.vue:11-24,52-59`、`ProfileView.vue:14-54,106-118,178-181`。
- **依据**：请求进行中模板为空白；详情非 404 错误只 toast 后仍空白；个人页笔记请求失败后可能显示“还没有作品”，误导用户。
- **改进**：加入标题/图片/资料骨架屏；区分 404、403、网络错误；提供页面级重试；Profile 的 profile 与 notes 请求分开呈现并保留各自错误态。
- **验收**：慢网下首屏 200ms 内出现骨架；失败后页面有可读说明和重试；404 文案只用于真实 404；重试不会重复追加卡片。

### F-05 发布页客户端文件校验和任务生命周期不完整

- **位置**：`PublishView.vue:35-54,56-76,79-101,104-115`。
- **依据**：点选文件 `onPick` 不检查 MIME、大小或空文件（仅拖放检查 `image/*`）；与 `docs/03-MVP实施与Docker部署.md` 的“客户端先行校验张数/大小/mime”不一致。上传是 fire-and-forget；删除/重传时不会取消旧请求，也不会删除旧 media。
- **改进**：统一 `validateFile`（扩展名+魔数由后端最终裁决，前端限制 MIME、单文件/总大小）；为每项维护 AbortController；删除/替换/离开页面时取消任务、`URL.revokeObjectURL`，对已拿到的孤儿 `mediaId` 调 `DELETE /media/{id}`；限制并发度为 3；展示实际进度与失败原因。
- **验收**：选择非图片、超限图片立即阻止并给出单项提示，不发请求；删除上传中项目后无状态回写、无孤儿 media；重传只保留一条 media；离开发布页对象 URL 数量不增长；并发请求最多 3 个。

### F-06 发布允许“部分图片 ready”时提交，导致意外丢图/孤儿任务

- **位置**：`PublishView.vue:24-28,104-115`。
- **依据**：`canSubmit` 只要求至少一张 `ready`，而选中的 `uploading/processing/fail` 会被静默过滤。用户选 3 张图、其中 1 张失败时仍可发布，界面没有明确告知另外两张不会进入笔记。
- **改进**：默认要求所有已选项 `ready` 后才能提交；失败项提供移除/重传；若产品确实允许部分发布，提交前必须弹出明确确认并显示将忽略的文件清单。
- **验收**：存在非 ready 项时按钮禁用且显示原因；所有 ready 后按钮可用；提交 payload 与预览顺序一致且无重复 mediaId。

### F-07 本地预览和图片加载缺少释放/降级策略

- **位置**：`PublishView.vue:58-63,79-81`、`NoteCard.vue:17-28`、`ProfileView.vue:128-145,188`、`NoteDetailView.vue:83-90`。
- **依据**：`URL.createObjectURL` 从未 revoke；多数图片没有 `@error`/占位图，MinIO URL 失效时显示浏览器破图；详情直接加载原图，缺少尺寸/响应式 srcset。
- **改进**：统一 ImageWithFallback；封面失败显示可访问占位；组件卸载、删除、发布成功时 revoke；详情优先 thumb/压缩 URL，点击再查看原图；补 `width/height` 或 aspect-ratio。
- **验收**：断开图片 URL 时布局不抖动且有可读占位；连续选择/删除 100 张图后内存和 object URL 不持续增长；LCP 和详情网络负载有基线数据。

### F-08 小屏导航控件折行，核心操作不可用

- **位置**：`TopNav.vue:39-57,95-101`。
- **依据**：`320x700` 截图中“发布”变成两行、“登录/注册”变成三行，按钮仍固定 `h-9`；没有移动端菜单或文字隐藏策略。
- **改进**：按钮文案 `whitespace-nowrap`；≤360px 使用图标+tooltip、紧凑间距或折叠菜单；保证触控目标至少 44x44；发布入口保留可发现性。
- **验收**：320/360/390/768/1280 宽度下无文字裁切、无横向滚动，按钮可点击，主题切换和头像菜单仍可达。

### F-09 表单无显式 label，键盘和辅助技术支持不足

- **位置**：`LoginView.vue:74-113`、`PublishView.vue:184-225`、`ProfileView.vue:145-169`。
- **依据**：登录、发布、资料编辑输入仅依赖 placeholder；Tab 双态没有 `role=tab/aria-selected`；上传删除/前移/后移仅有 `title`；焦点样式不统一且没有全局 `:focus-visible`。
- **改进**：每个输入绑定 `<label>`/`for` 和错误 `aria-describedby`；Tab 使用语义 tablist；图标按钮补 aria-label；统一键盘焦点和 ESC 关闭弹层；注册密码用 `autocomplete=new-password`。
- **验收**：仅键盘可完成登录、发布、编辑、删除确认；axe 或等效审计无严重表单/按钮问题；缩放 200% 无内容遮挡。

## P2：产品完整度、视觉系统与工程质量

### F-10 视觉层级单一，缺少社区产品关键反馈

- **位置**：`TopNav.vue`、`HomeView.vue`、`NoteCard.vue`、全局 `assets/main.css`。
- **观察**：首页只有双列图片，暂无页标题、筛选/排序、刷新入口、卡片操作反馈；大量 emoji（🏔、🌙、📄、📍、🔒）与按钮内手写 SVG 混用，风格不一致；空态和 404 使用随机 emoji，品牌识别弱。
- **改进**：建立少量统一 icon 组件（线性图标、语义色）；增加卡片 hover/focus、作者/媒体计数可点击反馈；首页加入可选“最新/关注”信息架构（后端支持后启用）；空态使用统一插画/占位组件，避免装饰性 emoji。
- **验收**：设计令牌集中管理，亮/暗主题对比度达到 WCAG AA；桌面、平板、手机截图通过视觉走查；交互状态（hover/focus/disabled/loading/error/empty）均有组件样例。

### F-11 图片社区基本能力缺失（需列入后续开发，不应伪装成已完成 MVP）

- **范围**：点赞、收藏、评论、关注、搜索/标签、通知、笔记编辑、草稿/失败恢复、内容举报与后台审核、视频/地点坐标。
- **依据**：当前前端路由和 API 只有登录、feed、发布、详情、个人资料/笔记；`docs/01` 明确多项为二期，但用户体验层没有能力占位或路线说明。
- **改进**：在后续开发文档按领域拆分接口契约、数据迁移、权限矩阵、通知和审核状态；先定义可演进的 UI 插槽，避免把点赞/评论临时塞入 NoteCard。
- **验收**：每个二期能力有 API/DB/UI/测试/回滚条目和证据报告；未实现功能不会显示“可点击但无响应”的假入口。

### F-12 工程门禁不足，回归依赖手工剧本

- **位置**：`frontend/package.json` 仅有 `dev/build/preview`；整个 `frontend/src` 没有项目级测试文件。
- **改进**：先补 Vitest 组件/Store/API 测试，再补 Playwright 浏览器剧本（路由复用、错误态、发布生命周期、响应式断点、主题和无障碍）；加入 lint/format/type-check，CI 以 build+test 为门禁。依赖添加前按 AGENTS 规则登记。
- **验收**：CI 可在干净环境运行；核心路径有稳定断言而非截图-only；失败日志不包含令牌或用户隐私；移动端和暗色主题至少各有一组回归。

## 建议交付顺序

1. P0：路由复用与服务端登出吊销，补测试后再合并。
2. P1：错误/加载状态、发布校验与任务清理、图片 fallback、窄屏导航、无障碍基础。
3. P2：视觉系统和产品能力路线；同步建立前端测试与 CI 门禁。
