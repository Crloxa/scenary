## 2. 共同开发规则

### 2.1 立项前五问

任何新功能开工前，必须在阶段文档或 ADR 中回答：

1. 用户在什么页面、因为什么动机使用它？
2. 新状态如何显示，失败后如何恢复，删除后如何撤销？
3. 是否需要新表/字段/队列/依赖？迁移和回滚是什么？
4. 哪些接口是公开的，哪些需要登录，资源所有权如何判断？
5. 最小可验证场景是什么，哪条命令或浏览器剧本能证明完成？

### 2.2 API 与数据演进

- API 继续使用 `/api/v1`；破坏性变更必须新增版本或提供兼容期。
- 新表使用 `Vn__description.sql`，禁止修改已应用 migration。
- 所有写接口优先设计幂等键、审计字段和软删语义；所有列表接口必须定义分页、排序和可见性。
- 跨模块只能调用 Service 门面；事件只新增 routing key 和队列，不复用已有队列语义。

### 2.3 通用验收门禁

每个阶段至少提交：

- API 契约更新与正反例。
- Flyway migration 验证（空库、已有数据、回滚/前向兼容说明）。
- 后端单测 + 集成/黑盒测试。
- 前端组件测试 + 一条浏览器主流程。
- 性能基线（样本量、p95、资源消耗）和安全边界。
- `docs/evidence/YYYY-MM-DD-阶段主题.md`，并同步 03 Checklist、HANDOVER、CHANGELOG。

## 3. P9 · 社交最小闭环

### 3.1 目标与边界

让用户对公开笔记产生最小反馈：点赞、取消点赞、收藏、取消收藏、关注/取消关注。P9 不做推荐算法、不做私信、不做评论，避免一次引入过多关系和通知。

### 3.2 数据模型建议

新增 migration（名称以实际落盘为准）：

```sql
CREATE TABLE note_likes (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  note_id BIGINT UNSIGNED NOT NULL,
  user_id BIGINT UNSIGNED NOT NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_note_user (note_id, user_id),
  KEY idx_user_created (user_id, created_at),
  CONSTRAINT fk_like_note FOREIGN KEY (note_id) REFERENCES notes(id),
  CONSTRAINT fk_like_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB;

CREATE TABLE note_bookmarks (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  note_id BIGINT UNSIGNED NOT NULL,
  user_id BIGINT UNSIGNED NOT NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_bookmark_note_user (note_id, user_id),
  KEY idx_bookmark_user_created (user_id, created_at)
) ENGINE=InnoDB;

CREATE TABLE follows (
  id BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  follower_id BIGINT UNSIGNED NOT NULL,
  following_id BIGINT UNSIGNED NOT NULL,
  created_at DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_follow_pair (follower_id, following_id),
  CONSTRAINT ck_no_self_follow CHECK (follower_id <> following_id)
) ENGINE=InnoDB;
```

计数不要只依赖 `notes.like_count` 的手工更新：写入关系表与计数更新必须在同一事务，或改为异步计数并接受明确的最终一致性。删除/私密笔记必须阻止新点赞，历史关系按产品决策保留或清理。

### 3.3 API 草案

| 方法 | 路径 | 语义 |
|---|---|---|
| PUT/DELETE | `/notes/{id}/like` | 幂等点赞/取消点赞 |
| PUT/DELETE | `/notes/{id}/bookmark` | 幂等收藏/取消收藏 |
| PUT/DELETE | `/users/{id}/follow` | 幂等关注/取消关注 |
| GET | `/users/me/bookmarks` | 当前用户收藏列表，游标分页 |

响应统一返回 `liked/bookmarked/following` 和计数，避免前端再发三次请求拼状态。公开详情匿名时不返回用户私有收藏状态。

### 3.4 验收

- 两次相同 PUT 不增加计数，两次 DELETE 不报错。
- 不能给私密/已删除笔记点赞；不能关注自己；被禁用用户关系不可创建。
- 并发 20 次点赞最终只有一条关系，计数与关系表一致。
- 首页和详情页登录/匿名视图差异明确，刷新后状态一致。

## 4. P10 · 评论与通知

### 4.1 目标

提供一级评论和对评论的回复，并把点赞、关注、评论统一成站内通知。P10 初版先用分页轮询；补充闭环增加不改变 HTTP 契约的原生 WebSocket 刷新信号、基础敏感词拦截、跨浏览器/读屏验收和正式压力基线。完整内容审核、人物检测和人工处置仍属于 P13 长期 TODO。

### 4.2 数据模型

`comments` 至少包含 `id/note_id/user_id/parent_id/content/status/created_at/updated_at/deleted_at`；`parent_id` 只允许指向同一笔记的评论。`notifications` 至少包含 `id/recipient_id/actor_id/type/note_id/comment_id/read_at/created_at`，所有关联字段允许为空以兼容不同事件。落地 migration 为 V5；评论列表按 `id ASC` 游标正序，通知按 `id DESC` 游标倒序。

内容限制：一级评论 500 字，回复 300 字；服务端做长度、纯文本（拒绝 HTML/脚本片段与控制字符）和 20 条/分钟频率限制，前端只做体验校验。

### 4.3 API 与交互

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/notes/{id}/comments` | 游标分页，按评论 id 正序，含已删除占位 |
| POST | `/notes/{id}/comments` | 创建一级评论或带 parentId 回复 |
| DELETE | `/comments/{id}` | 作者软删（当前无管理员角色） |
| GET | `/notifications` | 当前用户通知分页并返回未读数 |
| POST | `/notifications/read` | 按 id 批量标记已读，空数组标记全部 |

前端详情页评论区必须有：加载更多、提交中、失败重试、删除确认、空态、被删除占位、未登录引导。通知入口显示未读数，但不能因轮询失败阻塞主页面。

### 4.4 异步事件

本阶段采用同步通知：评论、点赞、关注和通知在同一 MySQL 事务内写入，提交后向在线用户发送原生 WebSocket 刷新信号，不新增 exchange、routing key、outbox 或 STOMP broker。通知量达到异步化门槛后，再按 01 文档新增 outbox 与事件消费者；P10 以数据库事务、幂等关系写入、断线轮询降级和黑盒失败证据保证闭环。

## 5. P11 · 搜索与发现

### 5.1 分阶段方案

先用 MySQL 前缀/全文索引完成可用搜索，再评估 Elasticsearch。不要在没有真实查询样本和性能数据前直接引入 ES。

第一阶段支持：标题、正文、地点名、作者昵称；过滤公开内容、已删除内容和禁用用户；结果按相关性再按时间稳定排序。本次 P11 选择**受控 LIKE**：它能覆盖中文、英文和特殊字符，查询词会转义 `%`、`_`、反斜杠，不把用户输入当作 SQL 模式；V6 只补充可见性、时间、作者和封面回表索引，不引入新依赖。标签字段、推荐算法和 Elasticsearch 不在本次首期交付范围，待有真实查询样本后另行立项。

### 5.2 API 草案

`GET /search/notes?q=&cursor=&limit=&sort=recent`，响应沿用 `NoteCardVO`，增加 `highlight` 可选字段。`q` 去除首尾空白后至少 2 个字符、最大 64 个字符；空查询和不足 2 个字符返回 40000，不返回全站数据。

- `sort` 取 `recent`（默认，按 `createdAt DESC, id DESC`）或 `relevance`（匹配标题 4 分、地点 3 分、作者昵称 2 分、正文 1 分，再按时间和 id 倒序）；其他值返回 40000。
- `cursor` 为服务端生成的 URL-safe Base64 opaque cursor，绑定查询词和排序方式，客户端不得跨 q/sort 复用；非法、过期格式或排序不匹配返回 40000。`limit` 默认 10，最大 20，超范围按公共分页约定收敛到 1~20。
- 结果字段为 `id/title/contentPreview/coverUrl/coverWidth/coverHeight/mediaCount/author/createdAt/social`，另有 `highlight`。`highlight` 是纯文本摘录对象（`title/content/placeName/author`），不含 HTML，未命中字段为 null，前端不得用 `v-html` 渲染。

### 5.3 索引与缓存

- P11 初版使用 MySQL 受控 LIKE，并新增 `V6__search_indexes.sql`：公开时间游标、公开作者连接和媒体封面回表各有合适索引；记录查询 p95 和慢查询样本。
- 首期不缓存搜索结果：结果受笔记软删和用户禁用状态影响，直接查询更容易保持权限实时一致；未来加缓存时 key 必须包含 query、sort、cursor、limit 和可见性视角，不能复用首页 L1。
- 若迁移 ES，新增 `search` 模块与 `note.published/note.updated/note.deleted` 事件，不让 Controller 直接写索引。
- `ops/rebuild-search-index.ps1` 只执行 `ANALYZE TABLE` 并输出搜索相关索引/EXPLAIN 结果；它不改业务数据。Flyway 迁移保持前向兼容，回滚通过备份恢复或后续受审查的反向迁移完成。

### 5.4 验收

覆盖中文、英文、特殊字符、空格、大小写、已删除、私密和禁用作者内容；结果无越权、分页无重复；V6 在空库和已有 V5 数据上可应用，重建脚本可重跑并输出索引与查询计划，查询 p95、迁移前向兼容和备份恢复回滚路径有证据。

## 6. P12 · 二期 A：视频上传与地点标注

### 6.1 视频上传

分两步做：

1. **基础链路（本轮 P12-01~P12-05）**：单文件后端代理上传，扩展 media 类型、大小和状态机；按容器/魔数识别 MP4/MOV/WEBM，限制 200MB、120 秒和 3840 长边，上传后进入独立 `video.transcode` 队列，生成封面和 480p/720p MP4。前端显示上传/处理中/失败状态，失败可删除后重传，并支持手工/地图坐标字段。
2. **体验优化（P12-E1，已完成）**：大文件改为 8MiB 分片/预签名直传，服务端只负责创建上传会话、合并和校验；引入断点续传、刷新恢复、离开页面保护和过期会话清理。图片仍保持后端代理上传。

新增状态至少区分 `UPLOADING/PROCESSING/READY/FAILED/EXPIRED`，不能复用图片的三态。视频发布前必须确保封面和播放地址就绪。

安全限制：扩展名不可信，必须检查容器格式/魔数；限制时长、分辨率、总大小和并发转码数；原始视频默认私有，播放地址使用短时签名或受控反代。

本轮实现约束：ffmpeg 只通过 `ProcessBuilder` 参数列表调用，不拼 shell 字符串；转码队列与图片缩略图队列、DLQ 独立；原始视频只保留 object key，响应只给封面和转码产物。当前 Compose 的 MinIO public-read 是既有 MVP 边界，P12 先保证原始视频不进入响应，私有桶/短时签名列入后续隐私增强。

### 6.2 地点标注

扩展 notes：`place_name` 保留，新增 `latitude/longitude/place_source/place_precision`。来源分为用户手填、EXIF、地图选择；本轮支持手工坐标和服务端 EXIF 只读回填，不引入外部地图供应商或前端地图依赖。EXIF 坐标只作为服务端候选值，除非用户明确选择分享，否则不进入公开响应。

API 可增加 `GET /places/reverse-geocode`，但必须有供应商超时、配额、缓存和隐私说明。地图展示优先使用 Leaflet 等轻量方案，新增依赖需走 01 §3.1 登记。（2026-09-11 已立项细化：逆地理编码见 §6.5，地图 UI 见 §6.6。）

### 6.3 验收

- 图片和视频队列互不阻塞，单一毒消息不会拖垮另一条链路。
- 转码失败可观测、可重试、可进入 DLQ；已发布内容不会暴露原始文件。
- EXIF GPS 测试夹具确认：公开响应不带 GPS；用户明确选择分享地点时才显示坐标。
- 大文件、断点、刷新、离开页面和重复提交均有浏览器回归。

P12 基础链路（P12-01~P12-05）已于 2026-09-04 通过出口门禁：V7 前向迁移、视频魔数与限制、独立转码/DLQ、480p/720p 产物、MAP/EXIF 地点隐私、前端发布与详情播放均已验证。证据见 [2026-09-04-P12视频与地点验收](evidence/2026-09-04-P12视频与地点验收.md)，学习沉淀见 [19-P12视频转码与地点隐私](learning/19-P12视频转码与地点隐私.md)。分片/预签名/断点续传已在 P12-E1 完成；私有桶短时签名、逆地理编码和地图 UI 仍属于后续增强范围。

P12-E1 施工约束：V8 新增 `video_upload_sessions` 与 `video_upload_parts`，分片对象使用会话 UUID 前缀；预签名 PUT 只允许写入当前会话对象，合并前服务端按对象实际大小校验并重新嗅探魔数，重复 complete 返回同一媒体。会话默认 2 小时有效，前端只持久化会话元数据和已完成片号，不持久化文件内容；离开页面保留会话，定时任务清理过期会话/分片对象。私有桶短时播放签名、外部逆地理编码和地图 UI 仍不纳入 E1。

### 6.4 增强包 E2 · 私有桶与短时签名（已立项，2026-09-11）

**目标与实测依据**：当前 Compose MinIO 为 public-read，浏览器读取全部走 `{publicHost}/{bucket}/{key}` 直链（`MinioService.publicUrl`），预签名能力只有 E1 的 PUT。2026-09-11 审计实测（[project-audit-2026-09-11](project-audit-2026-09-11.md) 探针 3/4）确认两个隐私缺口：① 私密笔记封面/图片 URL 任何持有者可匿名读取；② 匿名可对任意对象 key 做存在性探测（不存在 404 而非 403）。E2 把桶收敛为私有，所有浏览器读取改为运行时短时预签名 GET，"URL 即授权"收敛为"URL + 短时签名即授权"。

**数据与 URL 语义迁移（核心）**：`media.thumb_url/url`、`notes.cover_url`、`users.avatar_url` 现持久化直链 URL。E2 起这些列改存（或解释为）object key，读路径一律运行时生成签名 URL，不再持久化任何会过期的 URL。历史数据用扩展版 `ops/migrate-media-urls.ps1`（先 `-Preview`）把存量 URL 解析回 key。

**缓存语义**：feed 两级缓存与 `note:card:{id}` 中的 `NoteCardVO.coverUrl` 必须改为缓存 object key、VO 组装时实时签名——MinIO S3 签名是本地 HMAC 计算无网络 IO，压测需对比 P10 基线确认无回退；搜索、详情、公开主页同规则。

**任务分解**：
- E2-1 签名读能力与桶策略脚本：`MinioService.presignGet(objectKey, expiry)`（复用 `presignClient` + `Method.GET` + `addPathPrefix` 同源反代机制）；`docker-compose.yml` minio-init 增加 `mc anonymous set none`；新增 `ops/set-bucket-policy.ps1` 支持 private/public-read 双向切换（回滚路径）；读路径留配置开关 `media.presign-read`（false 时暂走旧直链，双读期使用）。
- E2-2 读路径切换与历史回填：媒体/笔记/搜索/社交/feed 全部 VO 改"存 key、出签名 URL"，默认 TTL 300s 可配；缓存改存 key；历史 URL 批量回填为 key（Preview→执行→抽查）。

### 6.5 增强包 E3 · 外部逆地理编码（已立项，2026-09-11）

**目标**：把已存的 `latitude/longitude` 变成人类可读地名候选；发布选点后自动回填可编辑的 `place_name`，详情页地名不再依赖用户手输。

**供应商决策（隐私边界）**：用户坐标属隐私，禁止把坐标外发给第三方公有 API。方案为自托管容器（Nominatim，或更轻的 Photon）：坐标只在内网流转；容器与数据导入体积在 01 §3.1 登记（已有"反向地理编码供应商"行，何时装更新为 E3 开工时）。provider 做成 `place` 包内门面 SPI + 配置开关：未启用/超时（2s）/失败一律返回空候选，前端保留手工输入，绝不阻塞发布。

**API 契约（v1.8，v1.7 已被 P16 夹缝任务包使用）**：`GET /api/v1/places/reverse-geocode?latitude=&longitude=` → `{placeName, provider, cached}`；仅登录用户可用；限流 30 次/分钟/用户（复用 P15 `RateLimitService` 与 `TOO_MANY_REQUESTS` 码）；Redis 缓存按 geohash-5（≈4.9km 网格）为 key，TTL 30 天。

**数据**：notes 不新增列；逆地理结果只作为发布页的 `place_name` 候选值，必须经用户确认，不静默覆盖已填地名。

**任务分解**：E3-1 provider SPI + 容器编排 + 配置/依赖登记；E3-2 API + 缓存 + 限流 + 降级（契约 v1.6 同步 02）；E3-3 发布页选点联动回填候选地名；E3-4 验收（JUnit + 黑盒 + Vitest；断言容器无公网出联、超时降级、缓存命中、限流 429、隐私不外发）。

**回滚**：配置关闭 provider → 接口稳定返回空候选/明确错误码，前端隐藏自动回填入口；容器整体摘除无数据迁移。

### 6.6 增强包 E4 · 地图 UI（已立项，2026-09-11，依赖 E3）

**目标**：发布页地图选点（点击/拖动 marker → 写入 `latitude/longitude`，`place_source=MAP`），详情页对带坐标笔记渲染小地图；与 E3 联动实现"选点 → 地名候选 → 可编辑确认"。

**依赖（走 01 §3.1 登记）**：前端新增 `leaflet`（及按需 dynamic import 拆包）；瓦片源默认 OpenStreetMap 公共瓦片（需出网，验收环境必须声明；提供本地/离线瓦片作为可选替代，未准备瓦片时组件整体降级为坐标文本展示）。

**边界**：不做路线/导航/附近的人/地理围栏；不做瓦片自建服务（除非出网被否后另行立项）。

**任务分解**：E4-1 依赖登记 + 地图选点组件（动态 import，feature flag `VITE_ENABLE_MAP` 可整体摘除）；E4-2 发布页集成（选点写入坐标 + E3 地名候选 + 手工坐标输入保留作为键盘可达替代路径）；E4-3 详情页展示（仅有坐标时渲染，无坐标零布局抖动）；E4-4 验收（Vitest、构建、三浏览器、390px 移动端、flag 关闭回归、可访问性：地图操作均有键盘/文本替代）。

**回滚**：`VITE_ENABLE_MAP=false` 整体摘除组件，无数据迁移、无后端变更。

## 7. P15 · 账号与安全基线（2026-09-11 立项，2026-09-12 完成）

### 7.1 目标与实测依据

2026-09-11 全栈实测审计（环境、命令、结果见 [project-audit-2026-09-11](project-audit-2026-09-11.md））确认以下缺口，合并为一个安全基线阶段：注册限流的 IP 归因缺陷（限流存在但全站共享 nginx 出口 IP 的单一配额桶，勘误与修正见审计文档 §7）；社交/发笔记/上传写接口无频率限制；安全响应头全部缺失（X-Frame-Options/X-Content-Type-Options/Referrer-Policy/CSP）；users 表无 email、无密码找回端点（忘记密码即永久丢失账号）；无账号注销；通知表无清理策略（无限增长）。私密笔记媒体公开可达由 E2 承接，不在 P15 重复。

### 7.2 任务分解

- P15-01 写接口限流基线：抽 `common.RateLimitService`（复用评论限流的 Redis INCR+EXPIRE 模式与 `ErrorCode.TOO_MANY_REQUESTS`）；注册 5 次/小时/IP（Redis 计数）+ 写接口按用户限流：发笔记 10/10min、点赞/收藏/关注 60/min、图片上传 30/10min；黑盒断言 429 与阈值边界。
- P15-02 安全响应头：nginx 全局增加 `X-Frame-Options: DENY`、`X-Content-Type-Options: nosniff`、`Referrer-Policy: strict-origin-when-cross-origin`；CSP 先 `Content-Security-Policy-Report-Only` 观察一版再 enforce（`index.html` 存在 2 处内联脚本，需先盘点）；HSTS 仅在启用 TLS 的部署形态开启（登记为部署项，不在 http 开发环境启用）。
- P15-03 密码找回（分两步）：a) 无新依赖过渡——`ops/reset-user-password.ps1` 运维脚本经 Compose 容器生成一次性重置入口；b) V9 给 users 增加可空唯一 `email` + 重置令牌表（15 分钟单次有效）+ `spring-boot-starter-mail`（01 §3.1 登记后安装）；SMTP 凭据仅入 `.env`。
- P15-04 账号注销：`DELETE /api/v1/users/me`（密码二次确认）→ 用户 status=2 注销态、昵称置"已注销用户"、bio/头像清理、名下全部笔记与评论软删、会话与刷新令牌吊销、用户名保留占用防冒名；对齐既有禁用账号在 feed/搜索/详情的可见性边界；契约进 02。
- P15-05 通知生命周期：定时任务清理"已读且超过 90 天"的通知（复用 V8 会话清理的调度模式），先统计后清理并留运维脚本dry-run。
- P15-06 仓库与验收卫生：根目录 `/test-results/` 补入 `.gitignore`；审计探针正规化为 `docs/dev/test-p15-security.mjs`，作为 P15/E2 的可重复黑盒回归工具。

### 7.3 验收

## 8. 长期 TODO · P13 内容安全与审核

### 7.1 状态模型

将“可见性”和“审核状态”分开：`visibility` 表达公开/私密/删除，`moderation_status` 表达 pending/approved/rejected/manual_review。审核拒绝不能通过把 visibility 改成 2 混过去。

### 7.2 处理链路

```text
media uploaded
  -> thumbnail / metadata strip
  -> moderation.pending
  -> rules + optional person detector
  -> approved | rejected | manual_review
  -> note publish visibility gate
```

规则检测先做文件类型、尺寸、EXIF、哈希和基础敏感词；人物检测或第三方 AI 仅作为可插拔 consumer，必须有超时、重试、成本上限和人工兜底。

### 7.3 管理与审计

没有管理员角色前，不开放公网管理接口；先提供受保护的内部脚本/只读报表。每次审核决定保存 actor、规则版本、输入摘要、时间和原因，禁止保存不必要的原图副本。

## 14. P18 · 社区治理最小闭环：举报与屏蔽（2026-09-19 立项）

**目标**：为 UGC 社区补上最小处置闭环——用户可举报笔记/评论、可屏蔽用户；举报达阈值自动隐藏内容（等效转人工，对齐 P13"无管理员角色不开公网管理接口"边界，处置动作走内部脚本）。

**数据（V10）**：`reports`（id/reporter_id/target_note_id 可空/target_comment_id 可空/reason_code/reason_text/created_at，唯一键防重）与 `user_blocks`（id/user_id/blocked_user_id/created_at，uk 双向唯一）；notes 加 `report_count`（举报去重计数）。

**规则**：举报需登录，20 次/10min 限流；同用户同目标唯一；公开笔记 `report_count>=5`（可配）自动 visibility→3（审核隐藏态，仅作者与内部可见，feed/搜索/详情匿名与第三人不可见）；屏蔽后：屏蔽者在对方 feed/搜索结果/主页网格中对屏蔽人不可见（单向不通知）；被屏蔽人访问屏蔽者主页网格为空。reason_code 枚举 `SPAM/PORTRAIT/INFRINGING/OTHER`。

**任务分解**：P18-01 V10 迁移 + report/block 幂等写接口（02 v1.8）；P18-02 可见性过滤接入 feed/搜索/详情/网格 + 阈值自动隐藏；P18-03 前端（详情页举报入口与确认流、作者区屏蔽按钮、举报成功态）+ 内部处置脚本 `ops/list-reports.ps1`（dry-run 只读报表）；P18-04 验收（黑盒 `test-p18-governance.mjs`：举报去重/阈值隐藏/屏蔽可见性矩阵/匿名边界；JUnit + Vitest + 三浏览器）。

**回滚**：阈值调高即停用自动隐藏；屏蔽表清空即全量恢复；V10 前向迁移，回滚按备份恢复惯例。
