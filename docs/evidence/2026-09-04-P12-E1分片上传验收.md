## 3. 命令与原始结果摘要

- `docker compose config --quiet`：退出码 0。
- `docker compose up -d --build`：退出码 0；backend/frontend 镜像构建、重建和启动成功。
- `docker compose ps`：backend、MySQL、Redis 为 healthy；frontend、RabbitMQ、MinIO 为 running；入口为 `0.0.0.0:8081->80/tcp`。
- `docker compose exec -T backend wget -qO- http://localhost:8080/actuator/health`：`{"status":"UP"}`。
- `node docs/dev/test-p12-e1-upload.mjs`：最终 `PASS=11 FAIL=0`。
- 黑盒末项复核：`v8=1; tables=2`；V8 会话和分片表均存在。

### 3.2 后端、前端和浏览器

- `cd backend && mvn -q test`：JUnit `50/50`，Failures `0`，Errors `0`；输出中的 Mockito 动态 agent 提示是 JDK 未来兼容性 warning，不是测试失败。
- `cd frontend && npm test`：14 个测试文件，Vitest `33/33`。
- `cd frontend && npm run build`：Vite `107 modules transformed`，构建成功。
- `cd frontend && npx playwright test e2e/p12-video.spec.js`：Chromium、Firefox、WebKit `3 passed`。WebKit 首轮调度较慢，专项断言窗口已设置为 15 秒；未改变业务轮询和接口契约。
- 浏览器脚本使用仓库内视频/图片夹具并 mock HTTP 接口，覆盖发布页状态流、坐标提交、重复提交保护和详情页视频元素；真实 MinIO 直传、合并、转码和过期清理由 3.1 黑盒覆盖。

### 3.3 真实性与边界检查

- 预签名 URL 由服务端生成并通过 `/minio` 同源反代可达，PUT 请求未经过后端 multipart 代理；图片上传仍保持原代理路径。
- 黑盒 ④ 创建的媒体沿用 P12 `video.transcode` 链路，状态从 `11 PROCESSING` 进入 `12 READY`，封面及 480p/720p 播放产物可读；原始 `/orig/` 路径不出现在媒体响应。
- 黑盒 ⑧ 缺片合并固定返回 `40903` 且会话可继续补片；黑盒 ⑨/⑩分别覆盖取消删除与过期拒绝预签名。

## 4. 功能边界与回滚边界

- E1 仅优化视频上传；图片继续走后端代理，视频仍为单文件发布，不与图片混合。
- 前端只持久化文件指纹、会话 UUID、过期时间和已完成分片信息，不持久化文件内容；刷新后需重新选择同一文件才能恢复。
- 当前实现验证了正常上传会话的过期扫描与对象清理；私有桶/短时播放签名、外部逆地理编码、地图 UI、断点上传性能压测和生产级多实例协调不在 E1 覆盖范围。
- 已应用的 Flyway V8 不直接修改；如需回退，使用备份恢复或经评审的后续迁移，并同步清理会话分片对象。验收未执行 schema 或业务数据回滚。
- 本轮不执行 `docker compose down -v`，不清理未核对的历史 DLQ 或业务数据；黑盒产生的验收媒体/账号按现有交接规则保留，后续运维可按 owner 和时间核对。
