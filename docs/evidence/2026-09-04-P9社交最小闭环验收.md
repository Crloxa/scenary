## 3. 原始验证结果

### 3.1 Compose 黑盒

准备：清理本轮已识别的 Redis 注册限流键和首页缓存键；未清理业务数据库中的历史验收数据，脚本用户名使用时间后缀避免撞名。

命令：

```powershell
docker compose exec -T redis redis-cli DEL 'rl:register:172.19.0.7' 'feed:first:v1:version' 'feed:first:v1:6'
node docs/dev/test-p9-social.mjs
```

结果：退出码 `0`，`PASS=13 FAIL=0`。

13 项覆盖：

1. 匿名详情返回公开计数且不泄露个人关系状态；
2. 并发 20 次点赞只保留一条关系，计数为 1；
3. 并发重复取消点赞幂等且计数归零；
4. 重复收藏只建立一条关系；
5. “我的收藏”游标列表返回公开笔记；
6. 取消收藏幂等且列表移除；
7. 并发 20 次关注只保留一条关系，计数为 1；
8. 取消关注幂等且主页状态刷新一致；
9. 禁止关注自己；
10. 私密笔记不能点赞并隐藏存在性；
11. 被禁用用户不能建立关注关系；
12. 登录 Feed 返回统一 `social` 结构；
13. 删除笔记后不能新增社交关系。

首次脚本尝试曾出现 `PASS=12 FAIL=1`：发布后极短时序内 Feed 首次读取仍命中旧快照。诊断确认数据库已提交、详情和随后 Feed 查询正常；测试入口增加最多 5 次、每次间隔 50ms 的短暂重试，以覆盖 Compose 请求调度窗口，并保留失败输出而非吞掉错误。最终可复现执行为 `13/13`。当前边界是发布后首页读取采用短暂最终一致窗口，详情接口可立即读取已提交笔记。
