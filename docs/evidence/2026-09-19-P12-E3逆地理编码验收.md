## 2. 交付物清单

| 交付物 | 位置 |
|---|---|
| provider SPI | `backend/src/main/java/com/scenary/place/PlaceProvider.java`（`id()` + `reverseGeocode(lat,lng)`，实现必须自托管、失败返回空候选） |
| 自托管实现 | `place/NominatimProvider.java`：Spring 内置 `RestClient`（零新 Java 依赖），连接/读超时同用 `provider-timeout-ms`（默认 2s），Nominatim `/reverse?format=jsonv2`，优先 `name` 退回 `display_name` 并截断 128 列宽；海面 `error` 响应/异常/超时一律空候选 |
| geohash | `place/Geohash.java`：标准 base32 编码，无第三方依赖 |
| 服务编排 | `place/PlaceService.java`：限流 → 参数校验 → geohash-5 缓存（`place:rg:{geohash5}`，TTL 30 天）→ provider；**只缓存成功地名**（超时/失败空结果落缓存会污染网格 30 天）；provider 抛错也折叠为空候选（SPI 实现不可信兜底） |
| API | `place/PlaceController.java`：`GET /api/v1/places/reverse-geocode?latitude=&longitude=` → `{placeName, provider, cached}`；provider 关闭返回 `{null, none, false}` |
| 限流 | `common/RateLimitService.places()`：`rl:place:{userId}`，30/min/用户（`SCENARY_RATELIMIT_PLACE_PER_MIN`），超限 42001/429 |
| 拦截链 | `config/WebConfig` 登记 `/api/v1/places/reverse-geocode`（P18 学习 24 教训：白名单式拦截必须显式登记，漏登记=匿名可达） |
| 配置 | `application.yml` `scenary.place.*`（`SCENARY_PLACE_PROVIDER_ENABLED` 默认 false / `SCENARY_PLACE_PROVIDER_URL` / `SCENARY_PLACE_PROVIDER_TIMEOUT_MS` 默认 2000 / `SCENARY_PLACE_CACHE_TTL_DAYS` 默认 30） |
| 容器编排 | `docker-compose.yml` 新增 `nominatim` 服务：`mediagis/nominatim:4.5`，**挂 `geo` profile 默认不启动**，无 ports 映射（坐标不出内网），数据卷 `scenary-nominatim-data`，`FREEZE=true` 防重启重复导入；启用步骤见 compose 注释 |

## 4. 隐私断言（E3-04）

| 断言 | 证据 |
|---|---|
| provider 容器无公网出联/无发布端口 | `docker inspect scenary-mock-nominatim --format '{{json .HostConfig.PortBindings}}'` → `{}`；网络仅 `scenary_default` |

## 5. 边界与已知限制

1. **真实 Nominatim 数据导入未在本环境执行**：`--profile geo` 服务与数据卷就绪，但 OSM pbf 导入属环境级操作（体积/耗时大），启用路径的验收用同拓扑内网 mock（`docs/dev/mock-nominatim.mjs`）完成；真实 provider 仅换 `SCENARY_PLACE_PROVIDER_URL` 指向与响应形状（jsonv2 `/reverse`），语义已由 `NominatimProviderTest` 解析分支覆盖。
2. **空结果不缓存**：与 05 §6.5"缓存 TTL 30 天"的字面语义相比收窄为"成功地名缓存 30 天"——超时/失败的空结果落缓存会把整个 geohash 网格污染 30 天，属实现时的设计修正，已记 CHANGELOG。
3. **WebKit 路由拦截伪影**（≥30min 排查坑，沉淀 learning 25）：e2e 中 Playwright 多路由 LIFO 链 + expect 轮询组合在 WebKit/Windows 高并行下偶发 XHR 无响应（trace status=-1）；spec 以"每页单路由 + 平铺等待"根治，非应用缺陷（同形态 10+ 连跑无回归）。
4. p12-video.spec 因发布页新增逆地理调用补 mock（空候选=行为与 E3 前一致）；不 mock 时假令牌会打到真实后端 401 触发全局刷新流程——属测试夹具问题，非产品缺陷。
