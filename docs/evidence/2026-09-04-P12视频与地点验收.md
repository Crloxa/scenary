## 4. 功能边界与回滚边界

- 首期是单文件后端代理上传；视频只允许独立发布，不与图片混合。状态使用 `11 PROCESSING`、`12 READY`、`13 FAILED`，预留 `10 UPLOADING`、`14 EXPIRED`，不复用图片 `0/1/2`。
- 当前限制为单文件 200MB、时长不超过 120 秒、宽高最长边不超过 3840；仅以 MP4/MOV 的 ISO-BMFF `ftyp` 或 WebM EBML 魔数为准，不信任扩展名和客户端 MIME。
- 原始视频在服务端只作为 object key 读取；响应只给封面和转码播放地址。Compose 现有 MinIO public-read 是既有 MVP 边界，私有桶和短时签名未在本轮解决。
- EXIF GPS 只读候选值可存服务端，但 `EXIF` 来源公开详情不返回经纬度；只有用户明确提供 MAP/手工分享坐标时才公开坐标。未引入外部逆地理编码或地图依赖。
- 第一次转码失败已作为可观测缺陷修复；失败状态/原因和专用 DLQ 仍保留。生产运维需按 DLQ 检查/重放策略处理积压，不应直接 purge 未核对的队列。
- 未验证范围：分片/预签名直传、断点续传、刷新恢复、大文件上传进度、过期会话清理、私有桶/短时签名、外部逆地理编码、地图 UI、实体读屏器和生产规模性能；这些属于 P12-E1 或后续增强，不影响本轮基础链路结论。
- 回滚边界：不修改已应用的 Flyway V7 文件；如需回退，使用备份恢复或经评审的后续反向迁移，并同步清理/迁移视频对象与 media 状态。本轮未对业务 schema 执行回滚。
