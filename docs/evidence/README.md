# 验收证据链规范

本目录保存阶段验收报告。Checklist 的勾选只表示状态，不能替代证据报告。

从二期 A 开始，每个 Phase 或可独立验收的功能环节必须在进入完成态前提交一份 `YYYY-MM-DD-主题.md`，至少包含：

1. **验证对象**：Git commit、工作树是否有未提交改动、构建产物或镜像摘要。
2. **运行环境**：日期、操作系统、关键运行时版本、服务入口与部署方式；不得记录密码、Token、Cookie 或 `.env` 内容。
3. **需求映射**：逐项列出需求/契约、对应实现入口、验证命令或浏览器剧本、预期结果。
4. **原始结果摘要**：命令退出码、断言总数与失败数、健康状态、关键响应；失败项必须保留并标明阻塞或风险，不得只写“已通过”。
5. **可复现入口**：脚本、夹具和操作步骤必须在仓库内可找到；依赖外部状态时写明准备与清理方法。
6. **结论边界**：明确“已验证”“未验证”“部分验证”，以及未覆盖的人工体验、性能、安全或兼容性风险。

证据报告必须与 `docs/03-MVP实施与Docker部署.md` Checklist、`docs/HANDOVER.md` 测试矩阵和 `CHANGELOG.md` 的验收状态相互引用。任一必需验收失败、无法重跑或缺少报告时，不得把对应环节标记为完成。
