# 26 · E2E 视频媒体夹具三重坑：WMF 绕过拦截 / PNA 拦回环 / 假 Range 服务

- **日期**：2026-09-19 · 所属 P12-E4 验收期（波及既有 p12-video.spec）
- **现象**：`p12-video.spec.js`"发布视频→详情页播放"在组合并行跑中偶发失败，且失败浏览器轮转（webkit 为主、chromium 后来也挂）。失败时详情页正常渲染，但 `<video>` 被应用替换成"视频暂时无法播放"占位——是应用的 `@error` 降级逻辑触发，而非断言或选择器问题。
- **原因**（三重坑叠加，逐层排除后定位）：
  1. **WebKit(Windows) 的 `<video>` 媒体请求由 WMF 媒体进程直发**（UA=`NSPlayer/... WMFSDK`），完全绕过 Playwright 的网络拦截层。spec 里 `route.fulfill` 的 `/minio/...mp4` 假响应对媒体引擎不可见，请求穿透到真实 nginx → 私有桶 403 → video onerror → 应用标记媒体损坏。证据：nginx 访问日志出现 mock URL 的 403 请求，UA 全是 NSPlayer。是否失败取决于 403 与断言的竞态，故偶发。
  2. **Chromium 的 Private Network Access / Local Network Access**：改用本地 `http://127.0.0.1:PORT` 媒体服务后，`http://localhost:8081` 页面的跨源媒体请求被 Chrome 以"Permission was denied for this request to access the `loopback` address space"拦截——headless 下权限弹窗自动拒绝；响应头 `Access-Control-Allow-Private-Network: true` 与 `--disable-features=LocalNetworkAccess,...` 均无效（新版走权限授予路径）。
  3. **blob:/data: URL 在 WebKit/WMF 上完全不可用**：探针实验（同页面依次挂 `loadedmetadata`/`error` 监听）显示 blob: 与 data: 均 `error code=4 (SRC_NOT_SUPPORTED)`，且 blob URL 跨文档导航后失效；Chromium 三种全 OK。
  4. 附带坑：自建媒体服务若"伪 Range"（对任意 Range 请求回全量 body 却声明 `bytes 0-end/total`），媒体引擎探测中段/尾部（moov atom）时拿到错位数据 → 解码错误。
- **我怎么验证的**：
  1. `docker compose logs frontend` 抓到 NSPlayer UA 打 `/minio/scenary-media/video/p12-720.mp4` 403——请求确实穿透拦截；
  2. 写最小探针 spec：同一页面内对 blob/data/http 三种 src 挂 `loadedmetadata`/`error` 监听逐个验证（webkit：blob/data 都 code=4、http OK；chromium：全 OK），一次实验排除所有猜测；
  3. video 元素全局 `addEventListener('error', ..., true)` 捕获 `v.error.code/msg` + console 消息，拿到 PNA 拦截原文；
  4. 修 Range 实现前后对比、`SCENARY_FRONTEND_URL=http://127.0.0.1:8081`（同 IP 源）对照——排除/确认各假设。
- **可复用结论**：
  1. **E2E 媒体夹具按浏览器分策略**：chromium/firefox 媒体请求走网络栈、`page.route` 拦截可靠，用同源 URL（与生产一致，CSP media-src 'self' 天然放行）；webkit 必须给真实可达的 HTTP 服务（本仓库放在 spec 的 `beforeAll` 起带真 Range 的 node:http 服务，`testInfo.project.name === 'webkit'` 切换）。
  2. **自建 Range 服务必须真切片**（`bytes=a-b` 与后缀式 `bytes=-N` 都要正确回 206 + 对应 body），伪造 206 迟早被媒体引擎探测踩爆。
  3. **跨源 loopback 媒体在 headless Chromium 里没有干净的放行手段**（响应头/特性开关都不行）；要么同源、要么不跨源。
  4. 夹具跨源媒体会吃 CSP Report-Only 报告污染 console 断言——在夹具文档导航处剥掉该报告头（Report-Only 不阻断运行时行为，剥掉不改变被测行为）。
  5. **定位这类问题的最短路径是"让应用自己说话"**：全局捕获 video error 的 `code/msg` + nginx 访问日志对照，两轮实验就把三层机制钉死；比反复调超时/重试有效得多。
