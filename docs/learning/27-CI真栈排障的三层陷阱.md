# 27 · CI 真栈排障三层陷阱：YAML 数字化 / Hub 镜像下架 / 注解取证

- **日期**：2026-09-28 · 所属 CI 真栈化（E5 验收期）
- **现象**：推送后 GitHub checks 持续 failure，且失败点层层转移——最初 "Frontend test"（vitest Linux 崩溃），修后 "Compose stack up"（反复），再 "Wait stack healthy"（backend unhealthy），再 "Black-box smoke"（单断言）。远端日志匿名 403 不可读，长期只能靠推测。
- **原因**（三层独立陷阱，逐层剥开）：
  1. **YAML 数字化吞掉 JWT_SECRET**：job env 写 `JWT_SECRET: 01234567890123456789012345678901`（无引号），YAML 把整串数字解析为科学计数法 `1.23456789012346E+30`（30 字符 < JwtProperties 的 32 位下限）→ backend 启动即崩（`Binding to target JwtProperties failed`）。本地永不复现（本地 .env 的值带随机字母）。
  2. **MinIO 官方 Docker Hub 镜像已下架**：`minio/minio`、`minio/mc` 全部 tag/digest 均 "repository does not exist"（2025 年 MinIO 收回免费镜像事件）；本地能跑只因国内 mirror 有缓存、digest 是 mirror 本地的。GitHub releases 二进制（404）与 dl.min.io（410）也全灭。唯一可得源 = `bitnamilegacy/*` 归档镜像（且 gcr mirror 对其 cache miss 偶发）。
  3. **compose 依赖失败会移除容器**：backend unhealthy 后 compose 自动清场，事后 `docker compose logs` 为空——失败现场必须在运行窗口内捕获。
- **我怎么验证的**：把失败现场经 **commit comment** 回传（workflow 用内置 GITHUB_TOKEN 写、匿名 API 读，绕开日志 403 与注解 10 条上限）；base64+gzip 编码防转义；zlib 容错解截断流。逐层解码后 JWT 数字化一行定案。
- **可复用结论**：
  1. **workflow env 里任何"看起来是数字"的值必须加引号**——YAML 1.1 把前导零串当八进制/科学计数法，Spring relaxed binding 再转一次手，错误信息（Value: "1.23E+30"）与原始值面目全非。
  2. **第三方镜像会从公共仓库消失**（MinIO 事件）；CI 用镜像前跑 preflight pull 探针（`docker pull` 逐个验证），不可得源找归档替代（bitnamilegacy）并配 mirror.gcr.io + 重试拉齐 + `compose up --pull never`（运行时零拉取）。
  3. **compose 依赖失败 = 容器被清场**，日志取证必须挂后台轮询器（每 10s 快照）或两阶段启动（先起目标服务捕获 boot 日志，再起全栈）。
  4. **匿名读不到 Actions 日志（403）**，但 check-run annotations 公开可读、内置 GITHUB_TOKEN 可写 commit comments（需 `permissions: contents: write`）——"失败现场写评论"是免鉴权取证的合规通道。
  5. **黑盒脚本不得隐式依赖数据库既有数据**（e2e38 ⑧ 的翻页断言默认 feed 有历史笔记，全新 DB 上 hasMore=false）——断言所需数据在脚本内自种，且必须在被测缓存预热**之前**落库。
  6. 诊断注入本身两次弄坏 workflow（extglob 语法、heredoc 内嵌 python 缩进破坏 YAML 块）——**改 workflow 后必须本地 `yaml.safe_load` + `bash -n` 双校验**再推。
  7. **换服务镜像必须同步迁移容器内的命令工具链**（v2.48.2 补充）：minio-init 换 `amazon/aws-cli` 后 command 仍调 `mc`——镜像内无 mc，`until` 死循环建桶永不成；且 `docker compose config --quiet` 只校验 YAML 结构，覆盖不到运行时脚本层，坏命令静默通过 CI。换镜像前先用临时容器/隔离网络把新 command 真跑一遍（`--entrypoint /bin/sh` 覆盖 + 实际断言输出），再落 compose。同坑二次现身：`ops/set-bucket-policy.ps1` 经 `compose run minio-init` 调 mc，镜像换后同样必死。
