# 22 · P12-E2 私有桶切换的 key 语义与签名收口

> 关联 Phase：P12-E2 私有桶与短时签名（2026-09-12 完成）。

## 现象

桶切 private 并全量回归时，5 个既有黑盒套件共 9 处断言失败/崩溃，暴露三类问题：

1. 断言按"URL 等于直链/以 `_720.mp4` 结尾"写死——签名 URL 末尾是 `X-Amz-Signature` 参数，字符串级比较全部失效；
2. 断言正则 `\?X-Amz-Signature=...$` 要求签名参数在查询串首位——实际 SigV4 参数按字母序排列，Signature 在最后；
3. e2e 直接 `new URL(created.data.coverUrl)` 抛 `ERR_INVALID_URL`——发布响应里的 coverUrl 是**裸 key**（`thumb/202609/xxx.jpg`），暴露了一个我漏改的读路径。

## 原因

"改 URL 语义"不是改一个函数，而是改一张**读写契约网**：写路径（上传/缩略图/转码/头像/发布封面）要改存 key；读路径（媒体状态、笔记详情/网格/发布响应、feed 两级缓存、搜索、收藏、评论/通知头像）每一处出响应的字段都要签名。遗漏任何一处，要么功能断（裸 key 无法 GET），要么隐私漏（直接吐 key 虽然拿不到对象，但会暴露对象命名规律）。黑盒断言同理，它们是契约的可执行形态。

## 原理

1. **容忍式读（tolerant read）让迁移与切换解耦**：`viewUrl(stored)` 接受 key 或遗留 URL——是 http 就解析出 key，是 key 就直接签名；配置关闭时原样返回。于是"回填历史数据"和"切私有策略"谁先谁后都不破坏读路径，回滚模式也只是这一个开关。
2. **签名是本地 HMAC，收口在组装时最便宜**：S3 SigV4 预签名不产生网络 IO，所以缓存里存 key、序列化前一刻签名，既不进缓存（不会过期成死链）也不增加请求成本。收口点选在 `FeedService.sign()`（缓存/fresh 两条路共同汇合处），一处覆盖两级缓存。
3. **断言要用语义锚而不是字面锚**：对"会变的表示层"断言，比较稳定不变的部分——对象 `pathname`（所有权/位置语义）+ 是否携带签名（授权语义），而不是整串 URL。

## 我怎么验证的

1. 回填前后各跑一遍 `SELECT COUNT(*) ... LIKE 'http%'`（脚本 Preview 输出命中 365/218/218/26 行），执行后黑盒 ① 断言残留=0；
2. 漏洞复跑：无签名直链 403（改前 200）、伪造签名 403、匿名探测 403（改前 404）；
3. 漏改的发布响应裸 key 由前端 e2e 的 `ERR_INVALID_URL` 抓出——补签名后 30/30 全绿；
4. Range 206 验证视频拖动进度条在签名 URL 下仍可用。

## 可复用结论

- 做存储/URL 语义迁移，先 grep 出全部写点与读点列成清单再动手，**发布响应这类"顺带返回"的字段最容易漏**；
- 读路径用"容忍旧格式"的转换函数统一收口，迁移顺序就不再敏感，回滚也只是一个开关；
- 缓存里存 key、组装时签名，是"会过期的表示值"不进缓存的通用解法；
- 黑盒断言跟着契约走：契约改了表示层，先升级断言语义再跑回归，否则修复被误判为回归。
