## 3. 新识别缺口（06 未覆盖）

> 以下 5+1 项均为 2026-09-19 代码核查确认缺失、且 [06](06-功能拓展与候选立项规划.md) A/B/C 三类未收录的增量。建议档位沿用 06 §6 的 ①~⑥ 表述。

### N1 内容消费行为数据（浏览计数与埋点）——多档候选的共同前置 ⭐建议优先评估

- **现状证据**：V1~V11 迁移无 `view_count`/热度/曝光类字段；前后端 grep 无任何 impression/analytics/埋点逻辑；详情页与 feed 卡片均无浏览量展示。
- **为什么是缺口**：06 多处把"真实行为数据"设为前置——推荐算法翻案条件（06 §7"日活/行为埋点数据足够 + B5 先落地"）、B5 标签"有真实使用样本后再立项"、A3 物种树节奏——但**埋点本身在任何一期规划中都不存在**，前置条件永远无法被满足。这是候选池的"元缺口"。
- **建议方案**：最小闭环——notes 加 `view_count`（或独立 `note_stats` 表）+ 详情页 PV 上报接口（登录用户按 user+note 去重、匿名按 IP 粗去重，Redis SETNX + TTL，复用 P15 限流的 INCR 模式）；展示位先只在详情页（feed 卡片暂不展示，避免"热度焦虑"的产品争议）；不做全站埋点 SDK，只记 PV 一个事件。
- **规模**：S~M（一表一接口一展示位）。**建议档位**：与 B5 标签合并立项（"行为数据→标签→推荐"演进链的第一环），或作为下一批夹缝任务单独转正。

### N2 草稿箱（发布中断不丢文案）

- **现状证据**：`PublishView.vue` 无 localStorage/sessionStorage 草稿逻辑（localStorage 仅 user store 存令牌）；发布页刷新/退出即丢标题与正文；已上传媒体因 media 行独立存在不受影响，但图文关联关系丢失。
- **为什么是缺口**：内容社区的高频痛点；小红书式产品的标配（自动存草稿）。当前实现里"媒体已上传、文案丢失"的不对称让损失更明显。
- **建议方案**：第一步纯前端（localStorage 按用户暂存标题/正文/地点/媒体 id 集合，进入发布页恢复，发布成功清除，S 级零后端改动）；第二步如需跨端再评估云端草稿表（M 级，另行立项）。
- **规模**：S（第一步）。**建议档位**：夹缝任务（与 06 档位①同类，不触碰 E3/E4 施工面）。

### N3 评论点赞

- **现状证据**：V1~V11 无 `comment_likes` 表；`note_likes` 模式（V4）已验证可复制。
- **为什么是缺口**：同类社区评论区的标准互动；通知系统（P10）可直接复用"被点赞"类型。
- **建议方案**：照抄 note_likes 的表结构/幂等写/计数列/通知事件四件套；契约进 02。
- **规模**：S。**建议档位**：与 N2 同批夹缝任务；互动闭环优先级低于治理与分发，不抢队列。

### N4 缩略图多尺寸与 srcset（feed/地图页带宽优化）

- **现状证据**：前端组件无任何 `srcset`（grep 无果）；MQ 缩略图管线为单一出片尺寸语义（learning/14 与 test-thumbnail37 的"出片尺寸语义"断言口径）。
- **为什么是缺口**：双列瀑布流卡片宽度跨度大（390px~桌面双列），单一缩略图在 DPR≥2 的移动端要么模糊要么过量传输；E5 地图浏览落地后单屏媒体密度更高，收益放大。
- **建议方案**：ThumbnailConsumer 扩展 2~3 档宽度产物（如 320/640/1080），media 行存多档 key，VO 按 `srcset` 语法出口；E2 签名语义不变（每档运行时签名）；缓存键随宽度分档。
- **规模**：M（管线+VO+前端三处）。**建议档位**：排在 E4 完成后、E5 之前评估（E5 大量加载缩略图前把带宽面收窄）；涉及媒体管线语义，动工前按 05 §2.2 过一遍契约影响。

### N5 公共 SEO 面：robots.txt / sitemap.xml（并入 B6，不单独立项）

- **现状证据**：`frontend/index.html` 无 og: meta；`frontend/public/` 仅 favicon，无 robots.txt / sitemap.xml。
- **为什么是缺口**：B6 分享卡片已覆盖 OG meta，但"搜索引擎可见性"这半边没人认领：当前 robots 缺失（爬虫行为不可控）、公开笔记无 sitemap。
- **建议方案**：作为 **B6 的扩充范围**——B6 转正时一并交付 robots.txt（默认允许 + disallow 私密路径）、公开笔记 sitemap（后端只读接口或构建期生成，二选一在立项时定）。不改变 B6 的规模档位判断（S~M → M）。
